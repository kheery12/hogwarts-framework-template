# LinkedIn Post - Hogwarts Framework v3

---

Just shipped v3 of the Hogwarts Framework for Claude Code, and I wanted to share what changed.

The biggest lesson from v2 was that telling an AI what to do is different from telling it what it cannot do. Constraints beat instructions. So v3 is built around NEVER rules - explicit boundaries that force precision in ways that positive guidance just doesn't.

What else is new:

Thinking mode now auto-detects when a problem needs deeper reasoning. No more manually toggling between quick answers and complex analysis.

The skill system got a complete overhaul. Skills are organized by "house" based on their function - Ravenclaw handles planning and research, Gryffindor does the building, Slytherin runs testing and validation, Hufflepuff manages integration and maintenance. Sounds whimsical, but it maps cleanly to how development actually works.

Remote control support lets you continue Claude Code sessions from your phone or browser. Start something on your laptop, pick it up from anywhere.

And Skill Forge - a protocol for creating new skills with built-in quality gates. Because the framework is only as good as the skills people add to it.

Someone in the community put it better than I could: "A prompt is a request. A Skill is a job description." That distinction shaped a lot of v3.

The whole thing is open source. Link in comments if you want to try it or contribute.

What patterns have you found that make AI tools more reliable?
